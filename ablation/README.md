# DDDQN/PER component ablation

The 2026 archive reconstruction pairs the four existing DDDQN/PER seeds with each of three one-component variants. Every variant completes four runs of 1,200,000 simulator interactions. The twelve new training runs total 14,400,000 interactions. The full reference weights are the published four-seed models from the same training configuration.

All runs use the same first 17,520 archive rows, 15-minute step, 75 kWh aggregate capacity, 37.5 kWh initial energy and 21 commands from −1 to +1 kW. The fixed random seeds, rewards, auxiliary action targets, and training and assessment windows are matched. The auxiliary targets use ten frozen models through step 80,000 and the sealed offline dynamic program thereafter. Both terminal regimes use the existing simulator and signed billing against zero storage.

- **Double DQN.** The same target network selects and values the next action using its maximum Q value, both in the Bellman loss and in replay-priority residuals.
- **Dueling.** The paired initial 15→128→128 feature stack feeds a single 119-wide hidden layer and 21 Q outputs instead of separate value and advantage streams. Parameter counts are 36,431 and 36,502 respectively.
- **PER.** Replay uses the same ring and batch size with uniform sampling with replacement, unit importance weights and no priority updates.

The tables report four-seed means. [Per-seed results](reference/per_seed.tsv) and the [paired summary](reference/summary.tsv) also give full-minus-variant differences. The equal-terminal wrapper uses the remaining archive availability to return energy to 37.5 kWh.

The comparisons quantify the effects of individual changes in this training-assisted, in-window simulator protocol. They do not separate the two training-assistance stages, quantify interactions between components, or establish effects on independent field inputs.

## Replay the evaluated models

Run from the repository root using the Python 3.8 CPU requirements in the parent README.

~~~sh
python ablation/replay.py --output component_replay.json
~~~

This checks the saved weights, action and physical trace digests, and performance metrics for 32 windows (16 models × two terminal regimes). It performs zero additional training.

## Repeat full training and audit

~~~sh
python reconstruction/run.py build-teacher
python ablation/train.py train --variant no_double --seed 0 --output ../ablation_runs/no_double_seed0
python ablation/audit_runs.py --runs ../ablation_runs --output ../ablation_audit
~~~

Run each of `no_double`, `no_dueling` and `no_per` with seeds 0–3 before running the audit. The full budget is fixed in `train` mode. The trainer writes all transition and update blocks and the verifier reads those blocks plus both saved evaluation traces. The public release distributes weights and reference digests. Full training journals are retained in the local archive or generated by retraining.
